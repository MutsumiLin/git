# 第一轮测试计划

测试对象为本轮实际实现的认证、行程计算、积分账本、商品查询和角色隔离。兑换库存交易、核销、清算尚未实现，不填写这些功能已通过。

## 基本路径法

选择真实 CarbonCalculator.calculate 的输入判断，按 Java 短路求值把复合条件分为五个判定：distance 为空、精度超过两位、低于最小值、高于最大值、mode 为空。该输入检查控制流图有五个二分判定，圈复杂度为 6；不包含库函数内部控制流。

| 路径 | 输入 | 期望 | 自动化对应 |
| --- | --- | --- | --- |
| P1 | distance=null | 拒绝 | unsupportedNullInputsAreRejected |
| P2 | 10.000 | 拒绝精度 | invalidDistanceIsRejected |
| P3 | 0 | 拒绝下界 | invalidDistanceIsRejected |
| P4 | 100.01 | 拒绝上界 | invalidDistanceIsRejected |
| P5 | distance=1，mode=null | 拒绝方式 | unsupportedNullInputsAreRejected |
| P6 | BUS，10.00，模拟 v1 | 1.200000 kgCO2e，120 分 | decimalMathAndFloorAreExact |

独立路径均执行后，再补零分、取整、不同方式、上界和高排放截零测试。控制流源文件见 docs/models/calculator-paths.puml。

## 等价类与边界

里程有效类为最多两位小数且 0.01—100.00；无效类为空、非数、零或负数、超过最大值、超过精度。交通方式有效 BUS/METRO/BIKE，无效 CAR/空。时间有效为过去带时区时间，无效为未来、格式不正确或空。

身份有效为已登录且角色允许，无效为未登录、错误角色、他人数据。请求编号有效为规范的未使用编号或相同内容重试，无效为格式错误、已有编号内容不同。

前端预览同时检查整数缩放计算，尤其 0.25 公里公交应为三分，避免 2.999999 的浮点向下取整错误。前端计算不决定真实发分。

## 集成与并发

完整链路：登录和 CSRF → 上报 → 事务和事件 → 行程、余额、流水 → 查询。两类并发分别使用八个独立事务：同编号仅一笔奖励；不同编号全部累加且不丢更新。

失败注入仅存在测试配置中：在发分监听之后抛异常，验证三张业务表回滚，原编号重试可成功。该异常不作为正常应用功能发布。

默认 H2 用于快速反馈；真实 MySQL 8.4 测试核对 SQL、锁和事务，独立测试库以 _test 结尾。HTTP 冒烟与实际后端重启另外验证真实会话和持久化。
